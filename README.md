# Форсайт-навигатор

Рабочая среда, в которой преподаватель вуза проходит форсайт-цикл: вход в цикл и шесть этапов (проблематизация → сканирование → сценарирование → картирование → экспертиза → интеграция). На каждом этапе есть задания с полями ввода, из ответов автоматически собирается проектный продукт. Итог витка — дорожная карта, пакет продуктов для курса и рефлексивное портфолио.

Форсайт-технология профессионального развития преподавателей вузов с использованием цифровых ресурсов. Автор — Соколова А.С., Самарский национальный исследовательский университет имени академика С.П. Королёва; научный руководитель — д.п.н., проф. Левченко В.В.; специальность 5.8.7.

## Стек

Vite + React 18 + TypeScript, react-router (hash-режим), zustand с persist в localStorage, vitest. Бэкенда нет: все данные хранятся в браузере. Резервная копия и перенос между устройствами делаются через экспорт и импорт JSON («Настройки»).

## Команды

```bash
npm install
npm run dev            # локальный сервер разработки, http://localhost:5173
npm test               # тесты: продукты p1–p6, правила этапов, промпты, версии карты, экспорт/импорт
npm run build          # статическая сборка в dist/
npm run check:terms    # проверка реестра ограничений ТЗ (раздел 1) по src/ и dist/
npm run extract-content  # заново перенести контент из source/forsight-navigator.html в src/content/
```

## Деплой

**GitHub Pages — одной командой:**

```bash
npm run deploy
```

Команда прогоняет тесты, собирает сайт, проверяет запрещённые формулировки и публикует `dist/` в ветку `gh-pages`. GitHub Pages показывает сайт из этой ветки: https://foresight-sokolova.ru (домен привязан файлом `public/CNAME`, DNS — в REG.RU)

**Автодеплой через GitHub Actions (по желанию).** Готовый workflow лежит в `ci/github-actions-deploy.yml`: на каждый push в `main` он делает те же проверки и публикует сайт. Чтобы включить его:

1. Переместите файл в `.github/workflows/deploy.yml`.
2. В *Settings → Pages* выберите *Source: GitHub Actions*.

Для push этого файла токену `gh` нужно право `workflow`: `gh auth refresh -h github.com -s workflow`.

**Vercel.** Импортируйте репозиторий: Framework — Vite, Build Command — `npm run build`, Output — `dist`. Или из терминала:

```bash
npx vercel --prod
```

Сборка использует относительные пути (`base: './'`) и hash-маршрутизацию, поэтому работает на любом статическом хостинге без настройки перенаправлений.

## Устройство

```
source/                     исходные материалы: HTML-прототип и ТЗ
src/content/                контент: перенесён из HTML скриптом без переформулирования (не править вручную)
  route.ts                  тексты маршрута из ТЗ: опоры этапов, связи лекций с заданиями
src/lib/                    логика без интерфейса
  answers.ts                схемы ответов по заданиям
  tasks.ts                  реестр заданий и правила их выполнения
  progress.ts               правила открытия этапов
  products.ts               сборка продуктов p1–p6 в Markdown
  prompts.ts                подстановка ответов в квадратные скобки промптов
  roadmap.ts                версии дорожной карты и сравнение v1 → v2
  run.ts                    витки, экспорт/импорт JSON, портфолио в Markdown
src/demo/demoRun.ts         демонстрационный пример (учебный, не данные апробации)
src/pages/                  экраны: старт, вход, этапы, итог витка, портфолио, библиотека, о технологии, настройки
```

## Демонстрационный режим

«Демонстрационный пример» на стартовом экране открывает заранее заполненный виток в режиме просмотра. Сценарий показа: старт → диагностика → этап II (карта факторов) → этап III (матрица и Дельфи) → этап IV (карта и прототип) → этап V (diff v1 → v2) → этап VI (динамика) → портфолио → «Начать виток 2». «Режим презентации» в полосе демо увеличивает масштаб: основной текст 20 px.
