# ТЗ: «Форсайт-навигатор» — приложение последовательного прохождения форсайт-технологии

## 0. Суть продукта

Это не описание диссертации и не справочник. Это **рабочая среда, в которой преподаватель вуза проходит форсайт-цикл**: шесть этапов подряд, на каждом — задания с полями ввода, из ответов автоматически собирается проектный продукт этапа, после шести этапов у преподавателя на руках дорожная карта собственного развития, пакет прикладных продуктов для своего курса и рефлексивное портфолио. Завершение шестого этапа запускает новый виток спирали.

Теория присутствует только как **опора перед заданием** (2–5 абзацев) и в разделе «Библиотека», куда можно уйти за полной лекцией. Концепция, результаты апробации, система условий — в одном экране «О технологии», вне основного маршрута.

Целевая аудитория — преподаватели вузов СНГ, любой дисциплины, без подготовки по форсайту. Один сценарий использования — индивидуальный проход (группа и фасилитатор возможны, но приложение не требует их). Второй сценарий — демонстрация на защите диссертации: показать прохождение за 5–7 минут на заранее заполненном примере.

## 1. Источник контента

Весь текстовый контент (этапы, позиции, требования, цепочки цифровых действий, группы ресурсов, промпты, шаблоны продуктов, лекции, критерии уровней, вопросы экспресс-диагностики, итоговые цифры апробации) **уже существует** в прилагаемом файле `forsight-navigator.html` — массивы `ZONES`, `STAGES`, `RGROUPS`, `INFRA`, `CONDITIONS`, `MODULES`, `REQUIREMENTS`, `LEVELS`, `RESULTS`, `DIAG_Q`, `PROMPTS`, `TEMPLATES`, `LECTURES`. Перенести их в `src/content/*.ts` **без переформулирования**. Новый контент в этом ТЗ — только задания (раздел 5); их формулировки тоже переносятся как есть.

Жёсткие ограничения на весь текст интерфейса:
- порядок этапов I → VI, зон, позиций, компонентов, требований — смысловой, никогда не алфавитный;
- термин «проектно-технологическая деятельность» не используется нигде; фамилия «Сдобняков» не упоминается;
- четыре признака технологии: педагогическая технологичность, проспективная направленность, андрагогическая укоренённость, цифровая опосредованность;
- цифры апробации воспроизводятся дословно из `RESULTS` и карточек раздела «Результаты» (110; 55 + 55; p > 0,05; r = 0,287 / 0,412 / 0,173; «в 2–3 раза»); ничего не округлять и не пересчитывать;
- «вузов» — множественное число в названии технологии.

## 2. Стек и ограничения

- Vite + React 18 + TypeScript. Маршрутизация — react-router (hash-режим, чтобы работало на любом статическом хостинге). Состояние — zustand с persist в localStorage.
- Без бэкенда в первой версии. Все данные пользователя — в localStorage; обязательны **экспорт/импорт JSON** (резервная копия, перенос между устройствами) и **экспорт портфолио в Markdown и в печать (PDF через браузер)**.
- Статическая сборка; деплой на GitHub Pages или Vercel одной командой. README с инструкцией.
- Язык интерфейса — русский. Шрифты: Unbounded (заголовки), Golos Text (текст), JetBrains Mono (промпты, формулы) через Google Fonts, с запасными стеками.
- Светлая и тёмная темы (системная + переключатель). Мобильная вёрстка обязательна: преподаватель должен мочь заполнять задания с телефона.
- Доступность: все поля с label, фокус видим, чекбоксы и радиокнопки нативные, `prefers-reduced-motion` уважается.
- Тесты (vitest): сборка продукта этапа из ответов; правила открытия следующего этапа; подстановка ответов в промпты; экспорт/импорт.

## 3. Информационная архитектура

```
/                 Старт: приветствие, выбор «Начать новый проход» / «Продолжить» / «Демонстрационный пример»
/start            Вход в цикл (этап 0): профиль, экспресс-диагностика установки, самооценка S
/stage/1 … /stage/6   Этапы цикла — основной маршрут
/portfolio        Мои продукты: шесть продуктов, версии карты, экспорт
/library          Библиотека: лекции, промпты, шаблоны (справочно, вне маршрута)
/library/lectures, /library/prompts, /library/templates
/about            О технологии: концепция, модель, ресурсы, результаты апробации, система условий (один длинный экран, контент из HTML)
/settings         Экспорт/импорт JSON, сброс, тема, демо-режим
```

Постоянная навигация: слева (десктоп) / сверху (мобильный) — спираль-прогресс с шестью узлами, текущий этап подсвечен, завершённые закрашены; номер витка.

## 4. Модель данных

```ts
type Run = {            // один виток спирали
  id: string; number: number;        // 1, 2, 3…
  startedAt: string; finishedAt?: string;
  profile: Profile;
  entry: { attitude: AttitudeResult; selfScore: {mc:number; kp:number; od:number} };
  exit?:  { attitude: AttitudeResult; selfScore: {mc:number; kp:number; od:number} };
  answers: Record<TaskId, unknown>;  // ответы по заданиям, схема — в разделе 5
  products: Record<'p1'|'p2'|'p3'|'p4'|'p5'|'p6', Product>; // собираются из answers
  roadmapVersions: Roadmap[];        // v1 после IV этапа, v2 после V
  reflections: Record<1|2|3|4|5|6, ReflectionPause>;
};
type Profile = { discipline: string; university: string; experienceYears: number; horizon: 5|10|15 };
type AttitudeResult = { retro: number; adaptive: number; prospective: number; dominant: 'retro'|'adaptive'|'prospective'|'mixed' };
type Product = { title: string; stage: 1|2|3|4|5|6; markdown: string; updatedAt: string };
type ReflectionPause = { content: string; process: string; done: boolean };
```

Хранить массив `runs`; активный — последний незавершённый. Новый виток создаётся только после завершения VI этапа и получает `number + 1`; его `/start` предзаполняется данными выхода предыдущего витка (установка, S, запрос на новый виток).

## 5. Маршрут: экраны и задания

### Общая структура экрана этапа

1. Шапка: римский номер, название, зона (цвет), позиция преподавателя одной строкой, прогресс по заданиям этапа.
2. **Опора** — свёрнутый блок «Что важно понять перед заданиями» (из `STAGES[n].aim`, `content`, `requirement`, `basis`; 1 экран текста). Ссылка «Полная лекция» ведёт в библиотеку, если у этапа есть лекции.
3. **Задания** — последовательно, одно раскрыто, остальные свёрнуты. У задания: номер, название, инструкция, поля ввода, кнопка «Использовать с ИИ» (если есть промпт), отметка «выполнено» (ставится автоматически при заполнении обязательных полей; можно снять).
4. **Продукт этапа** — живой предпросмотр: обновляется по мере заполнения, кнопки «Копировать», «Скачать .md», «Открыть в портфолио».
5. **Рефлексивная пауза** — два поля: «Что сделано на этапе» (содержательная рефлексия) и «Как это получалось: что помогло, что мешало, какие цифровые инструменты сработали» (процессуальная). На VI этапе пауза заменяется полным протоколом.
6. Кнопка «Перейти к этапу N+1». Правило: следующий этап открывается, когда выполнены **обязательные** задания текущего и заполнена рефлексивная пауза. Ссылка «Открыть досрочно» под кнопкой — доступна всегда, но этап помечается «пройден не полностью»; ничего не блокировать жёстко: аудитория взрослая.

Кнопка «Использовать с ИИ»: берёт промпт из `PROMPTS` по id, **подставляет в квадратные скобки уже введённые ответы** (дисциплина, горизонт, список факторов, сценарий и т.д.), показывает в модальном окне с кнопкой «Копировать» и подсказкой «Вставьте в YandexGPT, GigaChat или ChatGPT; ответ модели — черновик, решение за вами». Поле «Вставить ответ модели» рядом с заданием — необязательное, сохраняется.

### Этап 0 — Вход (`/start`)

- **0.1 Профиль**: дисциплина, вуз (необязательно), стаж (лет), горизонт работы с будущим (5 / 10 / 15 лет). Обязательно: дисциплина, горизонт.
- **0.2 Экспресс-диагностика установки**: 9 вопросов из `DIAG_Q`, результат — доминирующая установка с текстом интерпретации (тексты из HTML, функция `POST.diagnostics`). Результат сохраняется в `entry.attitude`.
- **0.3 Самооценка S**: три ползунка 1–10 по компонентам, вычисление S_инт = (S_мц + S_кп + S_од) / 3, уровень по порогам 8–10 / 5–7 / ≤4, критерии уровней из `LEVELS`. Пометка: «ориентировочная самооценка; экспертное оценивание — в программе». Сохраняется в `entry.selfScore`.
- Экран «Ваш старт»: установка, уровень, горизонт; кнопка «К этапу I».

### Этап I — Проблематизация (позиция: аналитик собственной практики)

Опора: три установки; задача этапа — не оценить себя, а сформулировать проблему, с которой пойдёт работа.

- **1.1 Дефициты форсайт-компетенции** (обязательно). Чек-лист из 10 позиций, отметить не менее 3 слабых: горизонтальное сканирование; выявление слабых сигналов; выход на системные противоречия; сценарное мышление; Дельфи-оценка; дорожное картирование; прототипирование образовательной инновации; коллегиальная экспертиза; трёхуровневая рефлексия; работа с цифровыми ресурсами (отдельно по шести группам — вложенный список).
- **1.2 Проблема профессионального развития** (обязательно). Три поля по шаблону «Противоречие между [что происходит в высшем образовании / моей области] и [как устроена моя практика]» для горизонтов 5, 10, 15 лет; радиокнопка «ведущая формулировка». Промпт 2.
- **1.3 Персональная ресурсная карта** (обязательно): образовательные задачи; возможности и ресурсы; 2–3 вектора движения. Промпт 1 — по желанию, для взгляда со стороны.
- **1.4 Делегируемые задачи** (необязательно; сквозной модуль по ИИ, задание 1): таблица «задача проектирования курса → как может помочь языковая модель», 3–4 строки.

Продукт p1 «Персональная ресурсная карта»: собирается из 1.1 (слабые позиции), 1.2 (ведущая проблема + остальные), 1.3, 1.4.

### Этап II — Сканирование (позиция: исследователь трендов)

Опора: работаем не с готовыми трендами, а с противоречиями, которые их порождают; что такое слабый сигнал. Лекция: «Генеративный ИИ в проектировочных задачах» (структура промпта).

- **2.1 Источники** (обязательно): список из 3+ источников — название, тип (база публикаций / агрегатор трендов / документ / экспертный материал), ссылка. Подсказка-список: eLibrary, Scopus, Google Scholar, Futures Platform, стратегические документы вуза и отрасли.
- **2.2 Факторы и слабые сигналы** (обязательно): карточки, минимум 6, из них минимум 2 помечены как слабый сигнал. Поля карточки: тип (Т — технологический, С — социальный, Э — экономический, Д — демографический, К — культурный); формулировка; свидетельство (источник, цитата или наблюдение); «тренд» / «слабый сигнал»; на что влияет в моей дисциплине. Промпт 3 подставляет вставленные фрагменты источников.
- **2.3 Генетически исходные противоречия** (обязательно): 1–3 формулировки «между … и …»; к каждой — мультивыбор карточек из 2.2, которые это противоречие порождает. Промпт 4 подставляет список факторов. Подсказка — три примера противоречий из диссертации (сложность знания ↔ когнитивные ресурсы субъекта; конвергенция технологий ↔ дисциплинарная организация знания; персонализация ↔ массовость).
- **2.4 Верификация** (необязательно): чекбокс «обсудил(а) карту с коллегой или экспертом», поле «что изменилось после обсуждения».

Продукт p2 «Карта трендов и слабых сигналов»: таблица факторов по типам, отдельный блок слабых сигналов, блок противоречий с привязанными факторами. Рубрика самопроверки под продуктом (четыре чекбокса из `STAGES[2].assessment`).

### Этап III — Сценарирование (позиция: сценарист-проектировщик)

Опора: прогноз против сценария; сценарии должны быть альтернативами, а не градациями; четыре эталонные конфигурации (технологическая автоматизация, гуманитарный ренессанс, конвергентное развитие, деглобализация). Лекции: «Нарративный дизайн курса», «Креативная методология CRAFT».

- **3.1 Сценарные оси** (обязательно): ось А и ось Б — неопределённый фактор и два полюса каждой. Подсказка: оси выбираются из противоречий 2.3 (показать их рядом).
- **3.2 Четыре сценария** (обязательно): матрица 2×2, в каждой ячейке: название; что происходит с содержанием дисциплины; что происходит с ролью преподавателя; ранний индикатор. Промпт 5 подставляет противоречия и горизонт.
- **3.3 Развилка** (обязательно): выбрать один сценарий, описать развилку, заполнить две таблицы «субъект (студент / преподаватель / университет) × горизонт (1 / 3 / 5 лет)». Промпт 6.
- **3.4 Мини-Дельфи** (обязательно): для каждого из четырёх сценариев — вероятность 1–10 и желательность 1–10 (свой голос). Поле «оценки панели» (если проходите в группе — внести средние по туру). Визуализация: четыре точки на плоскости вероятность × желательность.
- **3.5 Прикладная задача: нарративная концепция курса** (необязательно, но входит в продукт, если заполнено): базовый фрейм; идея-фрейм; роль студента; сюжетная линия; драма; польза; выбранный канон (путешествие героя / детектив / симуляция / экспедиция / свой). Это тренажёр сценарирования на материале собственного курса.

Продукт p3 «Сценарная матрица и банк сценариев»: оси, четыре сценария, диаграмма Дельфи, развилка, нарративная концепция (если есть).

### Этап IV — Картирование (позиция: стратег-картограф)

Опора: карта должна быть согласована со сценарием, каждая точка — измерима; стратегия в каждом сценарии. Лекции: «Модели педагогического дизайна», «Геймификация курса».

- **4.1 Целевой сценарий и стратегическая цель** (обязательно): выбор из четырёх (показать результаты Дельфи), цель на 3–5 лет одной фразой.
- **4.2 Дорожная карта** (обязательно): редактируемая таблица ключевых точек. Поля точки: горизонт (1 год / 3 года / 5 лет / 10–15 лет — ориентир); формулировка точки; что должно быть сделано; ресурсы; измеримый индикатор. Минимум по одной точке на горизонты 1, 3 и 5 лет. Промпт 7 (генерация конфигураций) и промпт 8 (проверка согласованности — подставляет всю таблицу и сценарий). Сохраняется как `roadmapVersions[0]` (v1).
- **4.3 Стратегии в остальных сценариях** (обязательно): для каждого из трёх других сценариев — одно действие, которое страхует карту, если реализуется этот сценарий.
- **4.4 Прототип образовательной инновации** (обязательно): название; формат (новый курс / модуль / цифровой модуль / программа); модель проектирования (ADDIE / SAM / ASSURE / 4C/ID — с краткой подсказкой, когда какая); образовательные результаты (2–3); таблица «результат → учебная стратегия → метод оценки → игровая механика» (пример из лекции по геймификации показывается как образец); карта пути студента по шести фазам (ориентация, погружение, консолидация, вызов, трансформация, завершение) — по одной строке на фазу.
- **4.5 Доска задач** (обязательно): пять ближайших задач с датами — первый горизонт карты, переведённый в действия.

Продукт p4 «Дорожная карта опережающего развития и прототип инновации». Рубрика самопроверки: горизонт, согласованность со сценарием, точки перехода, измеримость.

### Этап V — Экспертиза (позиция: эксперт-коммуникатор)

Опора: три критерия (реалистичность, инновационность, антропологическая состоятельность) с определениями; экспертиза — способ присвоить коллективный образ будущего, а не оценить человека.

- **5.1 Самоэкспертиза** (обязательно): своя карта v1 по трём критериям — оценка 1–10 и аргумент; три самых рискованных допущения.
- **5.2 Экспертиза карты коллеги** (обязательно): вставить текст карты коллеги (или нажать «Взять демонстрационную карту» — из демо-профиля), заполнить экспертный лист по трём критериям, три вопроса автору, главное условие реализуемости. Промпт 9 подставляет вставленную карту как черновик заключения. Кнопка «Скопировать заключение для коллеги».
- **5.3 Полученная обратная связь** (обязательно): вставить замечания коллег/экспертов (или текст ответа модели по промпту 9 на свою карту, если группы нет); по каждому замечанию — «принято / отклонено» и обоснование.
- **5.4 Корректировка карты** (обязательно): таблица 4.2 открывается в режиме правки, сохраняется как v2; рядом показывается diff v1 → v2 (что изменено, добавлено, удалено).
- **5.5 Согласование приоритетов** (необязательно, для группы): список приоритетов участников → совпадения / расхождения / формулировки для голосования. Промпт 10.

Продукт p5 «Экспертный лист и дорожная карта v2».

### Этап VI — Интеграция (позиция: рефлексивный практик)

Опора: три типа рефлексии по глубине; ценностное самоопределение; выход на новый виток.

- **6.1 Рефлексивный протокол трёх типов** (обязательно): содержательная (с подсказкой — список продуктов витка подставляется автоматически), процессуальная (подставляются рефлексивные паузы I–V этапов), рефлексия предпосылок (вопросы-подсказки: что такое образование и каково его предназначение; какова роль преподавателя в университете будущего; что означает «качественное обучение» при цифровой трансформации; каковы ценностные основания моего развития). Промпт 11 подставляет паузы.
- **6.2 Динамика** (обязательно): повторная экспресс-диагностика установки и повторная самооценка S; экран «до / после» — две установки рядом, три компонента и S_инт столбиками «вход / выход», пометка «самооценка, не экспертное измерение».
- **6.3 Ценностное самоопределение** (обязательно): из точек карты v2 отметить те, которые отобраны как антропологически состоятельные; одно предложение — «ради чего я иду по этой карте».
- **6.4 Мини-портфолио цифровых решений с ИИ** (необязательно): перечень делегируемых задач (из 1.4), три удачных промпта (выбор из использованных в витке — приложение ведёт лог нажатий «Использовать с ИИ»), одно задание, сгенерированное моделью и доработанное, вывод о потенциале и ограничениях.
- **6.5 Запрос на новый виток** (обязательно): новая проблема развития; чем она отличается от исходной (1.2 показывается рядом); критический этап следующего витка; дата и повод возвращения к карте (аттестация, новый семестр, новая технология). Промпт 12.

Продукт p6 «Рефлексивное портфолио». Кнопка «Завершить виток»: фиксирует `finishedAt`, показывает экран итога витка (шесть продуктов, динамика, запрос), предлагает «Начать виток N+1» (новый `Run` с предзаполненным 0.2/0.3 из `exit` и 1.2 из 6.5) и «Экспортировать портфолио».

## 6. Портфолио (`/portfolio`)

- Шесть карточек продуктов с датой обновления, статус (черновик / собран / этап завершён); открытие в режиме чтения с Markdown; «Копировать», «Скачать .md», «Печать».
- Блок «Дорожная карта»: версии v1, v2 (и дальнейшие по виткам), переключение, diff.
- Блок «Витки»: список `runs` с датами и динамикой установки.
- «Экспортировать всё»: один .md (титул с профилем, затем продукты по порядку этапов, затем рефлексии), один .json (полная резервная копия).

## 7. Библиотека (`/library`)

Справочный раздел, не входит в маршрут, но все его элементы доступны из заданий по ссылкам.

- **Лекции**: пять из `LECTURES` (геймификация, нарративный дизайн, CRAFT, модели педагогического дизайна, генеративный ИИ) + фильтр по этапу. Разметка: лид, разделы с подзаголовками. В конце каждой лекции — кнопка «К заданию, где это применяется» (3.5, 4.4, 2.2).
- **Промпты**: все 15 из `PROMPTS` с фильтром по этапу и копированием; здесь — в исходном виде с квадратными скобками (без подстановки).
- **Шаблоны**: шесть из `TEMPLATES` как пустые формы для тех, кто хочет заполнить вне маршрута (например, для коллег из группы); сохраняются отдельно от `runs`, экспортируются в .md.
- **Цифровые ресурсы**: шесть групп из `RGROUPS` и три уровня инфраструктуры из `INFRA` — таблицы, как в HTML.

## 8. «О технологии» (`/about`)

Один экран, контент дословно из HTML: концепция (двойное опережение, проспективная субъектность, четыре признака, триада, семь требований, три зоны), спираль модели (SVG из HTML, кликабельные узлы ведут в соответствующий `/stage/n`), результаты апробации (карточки и диаграмма из `RESULTS`), система обеспечения (`CONDITIONS`, `MODULES`, форматы реализации). Авторство: Соколова А.С., Самарский национальный исследовательский университет имени академика С.П. Королёва; научный руководитель — д.п.н., проф. Левченко В.В.; специальность 5.8.7.

## 9. Демонстрационный режим (для защиты)

- На стартовом экране — «Открыть демонстрационный пример». Загружает заранее заполненный `Run` с полным витком: профиль условного преподавателя (дисциплина выбирается нейтральная, например «Введение в проектную деятельность» для бакалавриата; **весь пример явно помечен как учебный и не выдаётся за данные апробации**), все задания заполнены содержательно и коротко, карта v1 и v2 различаются, Дельфи-диаграмма заполнена, динамика «до / после» показывает переход адаптивной установки в проспективную.
- Демо-прогон открывается в режиме просмотра с возможностью «Сделать копию и редактировать».
- В демо-режиме в шапке — тонкая полоса «Демонстрационный пример». Из любого места демо можно открыть «О технологии».
- Сценарий показа (должен укладываться в 5–7 минут кликов): старт → диагностика с результатом → этап II с картой факторов → этап III с матрицей и Дельфи → этап IV с картой и прототипом → этап V с diff v1→v2 → этап VI с динамикой → портфолио → «Начать виток 2».

## 10. Визуальный язык

Взять за основу `forsight-navigator.html`: токены цветов (светлая и тёмная палитры), три цвета зон (установочно-прогностическая, содержательно-форсайтинговая, рефлексивно-интегрирующая), спираль как главный образ, тот же набор шрифтов. Никаких эмодзи в интерфейсе, никаких «карточек со скруглением везде»: карточка — только там, где элемент нужно выделить. Таблицы — с горизонтальной прокруткой на мобильном. Поля ввода крупные, подсказки под полем, а не в плейсхолдере (плейсхолдер — только пример).

## 11. Критерии приёмки

1. Новый пользователь без подготовки проходит этап I за 15–20 минут, не открывая библиотеку; каждое поле понятно из подсказки.
2. Продукт любого этапа собирается из ответов без ручной правки и экспортируется в .md, в котором читаются все введённые данные.
3. Промпт из задания копируется уже с подставленными ответами пользователя; квадратные скобки остаются только там, где данных ещё нет.
4. Закрытие вкладки и возврат через неделю — весь прогресс на месте; экспорт JSON → очистка → импорт JSON восстанавливает всё, включая версии карты.
5. Демо-пример проходится по сценарию раздела 9 за 5–7 минут на проекторе: текст читаем с 5 метров (шрифт основной ≥ 18 px в демо-режиме или отдельный «режим презентации» с увеличенным масштабом).
6. Ни одной формулировки из реестра ограничений раздела 1 в сборке (проверка grep по исходникам в CI).
7. Lighthouse: доступность ≥ 95, мобильная производительность ≥ 85.
8. В тестах покрыты: сборка продуктов p1–p6, подстановка в промпты, правила открытия этапов, сравнение версий карты, экспорт/импорт.

## 12. Чего не делать

- Не превращать этапы в лекции: текст опоры не длиннее одного экрана, всё остальное — по ссылке в библиотеку.
- Не добавлять аккаунты, авторизацию, серверную базу, чаты — в первой версии только локальное хранилище и экспорт.
- Не встраивать вызовы ИИ-моделей по API: промпт копируется, ответ вставляется вручную.
- Не менять содержание заданий, этапов, продуктов и терминологию без согласования; любые новые тексты — только интерфейсные (кнопки, подсказки, ошибки).
- Не придумывать цифры: всё, что про апробацию, берётся из `RESULTS` и карточек раздела «Результаты».
